# 4ill.EffectsFilter

CounterStrikeSharp 1.0.376 / .NET 10. Общий фильтр чужой косметики, без зависимости от VIPCore.
`!fx`, `!effects`, `!hidefx` доступны всем: следы, ауры (включая Pet/Outfit), C4, эффекты убийства,
«Скрыть всё» / «Показать всё». Меню — штатный CenterHtmlMenu CounterStrikeSharp, как в VIPCore.
Свой эффект не скрывается настройками `!fx`; прежняя настройка собственного эффекта в модуле сохраняется.
Серверные выключатели отключают категорию для всех, включая владельца.

## Сборка и состав

`./build.sh` собирает локальный каталог `dist/`; ничего не выкатывает.

- `addons/counterstrikesharp/shared/FxFilterApi/FxFilterApi.dll` — одна общая сборка контракта.
- `addons/counterstrikesharp/plugins/4ill.EffectsFilter/` — плагин, deps.json, MySqlConnector.dll.
- `cfg/4ill_fx.cfg` — все шесть переключателей по умолчанию 0, исполняется при загрузке и смене карты.

Не кладите вторую копию FxFilterApi.dll в папки плагинов. В cs2-VIPCore используется та же DLL
из этого проекта (HintPath, Private=False); интеграция — ветка `claude/fx-filter`.

Пример автоматически создаваемого конфига
`addons/counterstrikesharp/configs/plugins/4ill.EffectsFilter/4ill.EffectsFilter.json`:

```json
{
  "Host": "127.0.0.1",
  "Port": 3306,
  "Database": "vip_global",
  "User": "fx_filter",
  "Password": "SET_LOCALLY",
  "ServerId": 1,
  "ConfigVersion": 1
}
```

`ServerId` — фактический ID сервера для метрики, даже при общем VIPCore sid=0.
Плагин использует только `player_fx_prefs`, `player_fx_events` (SELECT/INSERT/UPDATE)
и `vip_test_known_players` (SELECT). Таблицы создаются C6 общей схемы; резервный SQL
`sql/20261022_0001_fx_storage.sql` создаёт только таблицы фильтра. Плагин DDL не выполняет.
Для `fx_new_player_hidden 1` требуется заполненная C7 таблица известных игроков.
Незнакомый first_seen не считается подтверждённым новичком; ровно 7 дней — уже не новичок.

## Поведение

Настройки читаются асинхронно на входе и кешируются на сессию слота. Команды ждут завершения
чтения, поэтому старые настройки не затираются поздним ответом БД. При ошибке чтения — всё видно,
повторная `!fx` повторяет загрузку. Записи идут по очереди; настройки и метрика переключения
сохраняются одной транзакцией. При ошибке записи настройка действует до выхода, ошибка попадает
в лог; при следующем успешном переключении сохраняется полный текущий набор.
Синхронизация между серверами — при следующем входе, без опроса БД из CheckTransmit.

Подсказка без `[4ILL]` атомарно отмечается через `hint_shown_at`, одновременно с `first_hint`.
При выходе между фиксацией отметки и выводом сообщения повторной подсказки не будет.
События: `menu_open`, `toggle(category, hidden)`, `hide_all`, `show_all`, `first_hint`.
Владельцу скрываемого эффекта сообщений нет.

`fx_disable_trails|auras|c4|kill|rainbow` принимают 0/1 только из серверной консоли/конфига.
Создание выключенной категории блокируется; имеющиеся сущности удаляются игровым таймером
(до 0,25 с), до удаления убираются из снимков. Rainbow сбрасывается очередным тиком его таймера
(до 1,4 с). После обратного включения постоянные эффекты восстанавливаются при спавне/выборе.
`fx_new_player_hidden` по умолчанию выключен. XP-трейл, HitMarker/HitSound/Postprocessing не меняются.

Capability `4ill:fx` публикует `IFxFilter`. Дополнительный `IFxServerSettings` передаёт выключатель
Rainbow, потому что FakeConVar не является нативным ConVar. Общий `FxFilterProvider` сохраняет
один supplier и меняет экземпляр при reload: CSS сохраняет первый supplier после unload.
Unload немедленно возвращает false даже для кешированного модулями экземпляра.
Без плагина и даже без сборки API модули работают как раньше; capability перечитывается раз в секунду.

**KillIcon:** `player_death` не содержит отдельной transmit-сущности. В VIPCore реализована
пересылка исходной иконки скрывающим зрителям и выбранной — остальным. Она выключена по умолчанию
(`fx_killicon_per_client 0` в VIP_KillIcon): до проверки двумя CS2-клиентами иконка остаётся видимой.
`fx_disable_kill 1` отключает замену иконки независимо от экспериментального переключателя.
VIP_KillScreen рисует эффект только убийце и не фильтруется.

## Проверки

`tests/docker-storage.sh /path/to/4ill` использует уже работающий Docker-стенд сайта и отдельную
одноразовую БД `fx_validation_*`; рабочие/production базы не использует. Проверяет настоящий FxStore:
новичков, сохранение между серверами, конкуренцию подсказки, пять метрик и откат транзакции.
В cs2-VIPCore: `sh tests/FxFilterBridgeValidation/run.sh` проверяет отсутствие DLL/сервиса,
выгрузку и повторную загрузку с настоящим реестром capability CounterStrikeSharp.

Проверка двумя игровыми клиентами (раздел C8 плана) и css_profiler ещё не выполнены:
Docker сайта не содержит игрового CS2-сервера. До них пересылку KillIcon не включать.
Прод, платежи и боевые настройки серверов при разработке не изменялись.
